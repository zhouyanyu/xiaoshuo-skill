# 轻量原文定位

## 目标与范围

参考用户认可的《红楼梦》档案做法：章节回忆卡保持简洁，在章末用“段号链接＋检索词＋短摘录”让读者能立即回到原文。完整正文另存，不能把原文复制进每个人物页、关系表和章节笔记。此规则适用于任意小说，不固定某书的章号、段号或 EPUB 文件名。

有可读原文时默认使用；只有梗概或原文不可读时注明实际依据，不造段号、不创建假原文页。原著内容和用户书籍文件只留在其本地档案，不上传 skill 发布仓库。

## 原文页和段号

1. 在书籍目录下建立 `原文定位/`，每个实际章节单元一份有锚点的 Markdown 提取文本，例如 `第003回原文.md`。已有可用原文页就复用；不要同时强制维护同样内容的 TXT、Markdown、HTML 三套副本。机器处理中间文件按需要留在中间目录。
2. 按本版原文的阅读顺序及实际段落边界编号，通常用 `## 段1`、`## 段2` 等形成可点击标题。保留文本，不为凑定位点重新切句或合并段落。诗词、对话等按源格式处理，并在整理记录说明分段规则。
3. 原文页开头注明书名、版本、原章节名、源文件或 EPUB 内部文件及原有锚点，解释“段号是本版提取序号，不是纸书页码”。标题、注释是否计入段号须遵循已建立的本书规则并记录；同书不能中途切换规则。
4. 校注与正文区分。保留有用校注和原标号，不把编者解释当成角色行动，也不把校注编号冒充正文段号。
5. 编号和文件名建立后保持稳定。新增笔记或更正梗概不得重新编号原文；重新提取导致分段变化时，比较旧版、维护映射并同步全部受影响链接。不同版本不能复用未经核对的段号。
6. 原书合排的章节保留实际单元，如两回共一源文件且无法可靠分开，就保留合排和范围，不能为了凑“一回一文件”虚构边界。分开的章节也可共享同一源文件，须记录各自锚点或段落范围。

原文页含完整提取正文时，可以给读者作为检索材料；它不等于已经逐段精读。原文页提供返回章节回忆卡和阅读首页的真实链接。

## 章节里的定位条目

章末使用 `## 原文定位`：

- 一句来源说明：本版章节与必要的 EPUB 内部文件名，不重复堆叠长绝对路径。
- 一个“本章完整提取文本”链接。
- 通常选 3–5 个关键定位点；短章可减少，不按数量硬凑。身份揭晓、关系转折、关键因果、容易误读的对白和章末事件优先。
- 每条写“[段号](真实目标#标题) · 检索词‘关键词’：短摘录”，可加一句说明这段支持什么判断。关键词来自该段，摘录通常约 40–100 个汉字，只取辨认所需部分；用省略号明确裁剪，不拼接出原文没有的句意。
- 重要解释可直接复用这几个段落链接，不每句话追加来源表。少数定位点不能代表所有支线均已复核。

**按事件和上下文挑段落，不按人名的第一次命中机械选段。**例如要定位摔玉，就查实际摔玉段落，不能只链接“贾母”第一次出现的介绍段。先确认该段真的支持相应事件或解释，再写摘录。

普通 Markdown 从章节页到原文页使用相对链接；Obsidian 双链用明确的文件路径和标题。中文和空格允许规范百分号编码，但显示为短标签“段36”，不让编码长串占据阅读视野。源文件、段号、标题和引文都不能凭记忆编造。

## 核对与维护

- 点击式目标必须实际存在，标题或区块也必须存在。交付前运行 `scripts/check_wiki.py`；它已能检查原文页链接及标题，但不证明选段语义正确。
- 对每个定位条目，另核对关键词和摘录确实出现在目标段落，并确认上下文支持笔记结论。对照时可忽略纯排版空白，不能忽略否定、说话人或注释来源。
- 阅读首页或整理记录保留章节到源文件／锚点的映射，以及“已提取”“关键段落已核对”“已逐段精读”的实际状态；这些状态不能互相替代。
- 只更新受影响的定位点，复用既有原文页和稳定编号，保留用户手工批注；不要因加定位重建整套 Wiki 或增生空人物页。
