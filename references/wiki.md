# 阅读 Wiki 的文件维护

## 存放与入口

先沿用用户已有书籍目录和笔记结构。用户提供小说文件并明确选择或调用 `$xiaoshuo`，即授权按默认行为整理全书并保存 Wiki，无需再询问是否建档。新档案优先创建在用户指定的笔记位置；未指定时使用当前任务的用户交付目录，若无专用交付目录则使用当前工作区 `阅读笔记/书名-作者或版本标识/`。不猜测 Obsidian 仓库路径，不保存到 skill 安装目录。只问剧情或要求预览笔记时先在聊天回答，不擅自创建整套目录。

推荐结构：

```text
书名-作者或版本标识/
├─ 阅读首页.md
├─ 人物索引.md
├─ 故事时间线.md
├─ 线索追踪.md
├─ 全书速览.md
├─ 章节/
│  ├─ 第001章-原章名.md
│  └─ 第002章-原章名.md
├─ 人物/
├─ 地点与势力/
└─ 文化与背景/
```

未整理全书时“全书速览”明确标注已覆盖范围。没有相应内容的目录和页面不预先填充空架子。文件名替换系统不允许的字符，保留原章名在正文中；卷、回、序章等保留原有编号，同时给稳定排序，不擅自把原书章节重新划分。

阅读首页可以用 YAML 记录这些持久信息，字段未知时使用 null 或清晰的文字，不猜测：

```yaml
---
book_title: "书名"
author: "作者"
edition: "版本或来源标识"
reader_progress: null
spoiler_mode: "允许已核实的全书剧透"
source_coverage: "实际可用的材料范围"
processed_chapters: []
---
```

正文另列原文文件位置、已完成／待处理章节及本次更新范围。全书默认任务记录完整章节清单、各章处理状态和下次续接点；EPUB 额外记录目录到正文文件／锚点的映射。用户明确提供阅读进度时才更新 `reader_progress`；整理更多章节不自动推进读者进度。

## 每次新增章节

1. 读阅读首页、人物索引和与本章相关的已有页面，确认版本、别名和已有线索。
2. 阅读本章材料，建立原文顺序的场景记录、人物状态与关键因果；写入独立章节回忆卡。
3. 同步新增或变化的人物、重要地点与势力页。使用既有规范名；身份尚未确认时不要误合并。
4. 更新人物索引、故事时间线、线索追踪和速览，只补本章带来的信息及实际核实的后文解释。
5. 有实质探究内容时创建或更新背景页，记录来源和与剧情的关系。
6. 更新首页的处理范围、导航和必要的待核对项，检查链接，再报告交付。

大型任务按批次执行上述流程，及时保存。除非用户要求改造旧档案，不把新增一章扩展为重写全部旧笔记。

## 链接与定位

- 在明确的 Obsidian 仓库内，用仓库可解析的路径限定双链和显示别名，如 `[[书名目录/人物/规范名|人物名]]`；路径取自实际仓库结构，不能照抄示例。
- 仓库根未知或交付普通 Markdown 文件时，使用相对于当前文件的 Markdown 链接，如章节页到人物页的 `[人物名](../人物/规范名.md)`；路径含空格等时采用合法编码。
- 无法保存文件、只在聊天输出时，以人物名和章节定位代替悬空链接。
- 链接目标必须存在或本次同步创建。实体页反向链接到相关章节，章节页链接到相关实体；同名实体用书名或版本路径消歧。
- 每个关键事实至少有章节定位；精确引文或争议事实使用实际可核对的段落／页码。不要创建没有原文依据的段落编号。

## 版本、真相与更正

- 一个档案对应一个确定版本或来源范围。用户换版本时确认能否对应；无法确定的章节和页码不自动沿用。
- 本章事实正文保留当时状态。后文揭晓时追加独立的真相解释，并更新实体页和线索表，不把人物的误会删改成已知真相。
- 汇总页明确“截至第几章”或“全书核实”。全文真相与用户进度时的局势分别展示；允许剧透不等于两者混写。
- 用户要求不剧透时，新输出及新保存页面按进度过滤。既有全书档案可能含剧透，应说明并提供过滤后的入口，不未经请求删除既有资料。
- 更正内容错误时更新所有实际受影响的页面与索引；“原文如此、人物说谎”不属于原文错误。保留用户批注和感想，必要时将自动整理内容置于单独区块。
- 重复整理同一章时更新既有文件，避免重复建页、重复追加相同线索或因别名生成多份人物页。

## 交付前检查

- 请求的章节都有独立笔记，覆盖范围与首页一致；没有假称读过未处理材料。
- 人物别名一致，身份合并有证据；关键关系和结论能定位到来源。
- 场景顺序与真实时间不混淆，叙事切换没有被画成人物移动。
- 真相与人物当时认知分开；未解问题保留当时状态，揭晓有实际来源。
- 内部链接全部有目标，实体页能回到章节；文件名稳定，不产生重复人物和重复章节。
- 背景页有真实资料或明确的待查证状态，并回答它如何帮助理解剧情。
- 图表语法保持简单，代码围栏闭合；有渲染条件时检查可读性，未渲染时不要声称已验证渲染。
