# 小说阅读 Wiki · xiaoshuo

把小说整理成**读得明白、接得上剧情、以后查得到**的阅读档案。

这是一套给 AI 阅读助手使用的 skill：它指导助手阅读你提供的小说，生成逐章回忆卡，并维护人物、场景、时间线、线索和文化背景。它不是独立运行的软件，也不是预先整理好的小说资料库。

默认允许剧透，但只使用有依据的后文信息；始终区分“本章人物当时知道什么”和“全书后来揭晓了什么”。

**最简用法：附上小说文件 → 选中 `xiaoshuo` skill → 发送。**无需填写章节范围、保存路径或长提示词，默认逐章整理全书并保存阅读 Wiki。

## 适合解决什么问题

- 人物太多，姓名、外号、尊称记不清。
- 作者切换地点、视角、倒叙时，弄不清谁在哪里。
- 知道发生了什么，却不理解为什么发生、人物为什么这样做。
- 隔一段时间继续读，忘了前情和未解决的问题。
- 读完整本书后，想快速回忆主线或查找某段情节。
- 想了解官职、礼俗、宗教、典故、地理等背景，以及它们如何影响故事。

## 安装

### Codex：安装到个人 skills 目录

将仓库克隆到 `xiaoshuo` 文件夹。**安装目录叫 `xiaoshuo`，调用名称也是 `$xiaoshuo`**；GitHub 仓库名称 `xiaoshuo-skill` 不影响使用。

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Path "$env:USERPROFILE\.codex\skills" -Force | Out-Null
git clone https://github.com/zhouyanyu/xiaoshuo-skill.git "$env:USERPROFILE\.codex\skills\xiaoshuo"
```

macOS / Linux：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/zhouyanyu/xiaoshuo-skill.git ~/.codex/skills/xiaoshuo
```

如果你的 Codex 使用自定义 `CODEX_HOME`，将目标改成其下的 `skills/xiaoshuo`。有可用 GitHub SSH 认证时，也可将远程地址换成：

```text
git@github.com:zhouyanyu/xiaoshuo-skill.git
```

**已存在 `xiaoshuo` 目录时不要直接重复 clone 或删除旧目录。**先备份旧内容：如果原目录已从本仓库克隆，按下方更新方法拉取；若是以前手工安装的 skill，备份后将本仓库内容放入原目录，并检查自己的定制。

安装完成后，在聊天中用 `$xiaoshuo` 明确调用；如果当前聊天尚未识别新增 skill，可新建聊天后再调用。

### 不使用 Git

从 GitHub 下载 ZIP，解压后将包含 `SKILL.md` 的整个目录命名为 `xiaoshuo`，放入个人 skills 目录。需要同时保留 `agents/`、`references/` 和 `scripts/`，不能只复制 `SKILL.md`。

## 最快开始

附上小说 EPUB 等文件，选择 `xiaoshuo` skill 后发送即可。如果需要一句话，也只需：

```text
使用 $xiaoshuo 整理这本书。
```

默认会：

1. 读取书籍信息和目录，按原书章节识别正文。
2. 分批整理文件中的全部可读章节，每章一份回忆卡。
3. 持续维护集中人物档案、地点势力、故事时间线、线索追踪和全书速览；不为每个姓名建一个文件。
4. 使用中文，允许有依据的剧透，按需查证文化背景。
   每章末尾默认提供少量可点击原文定位，方便复查关键事件。
5. 沿用已有档案目录；未指定时保存到当前任务交付目录。没有专用交付目录时，保存到当前工作区的 `阅读笔记/书名-作者或版本标识/`。
6. 完成后给出阅读首页入口，并说明实际覆盖范围。

助手会说明采用的默认值并直接开始，不要求你逐项确认，也不把完成前几章当作完成整本书。长书在执行限制下若未能完成，会保存章节状态和续接点；没有配置后台任务时，不会声称将在后台自动继续。

只有想改变默认行为时才补充要求，例如“只做前三章”“不剧透”“保存到某目录”。也可以先试一章，不保存文件：

```text
使用 $xiaoshuo 整理下面这章，先在聊天里展示回忆卡。
允许剧透，但没有后文依据的内容不要猜。
```

### 需要提供哪些材料

优先提供**对应版本的原文**，并说明书名、作者、章节范围。可以粘贴文本，或提供助手当前环境能读取的文件。

- 只有几章：整理已有章节，不编造后文答案。
- 有全书：助手可以分批读取并用已核实的后文解释前文；不能只上传文件就声称已读完。
- 只有梗概或旧笔记：可以整理，但会标明依据及信息缺口。
- 只有书名：可以获得简要帮助，但不适合生成准确、可追溯的逐章档案。

TXT、Markdown 容易直接读取；EPUB 会优先使用环境已有解析工具，也可读取其 ZIP 内的 OPF、spine 和导航来确定章节顺序、提取正文。不能把一个 HTML 文件机械等同于一章。PDF 提取取决于环境工具，扫描 PDF 可能还需要 OCR。加密或损坏的书籍会明确报告无法读取的部分。本 skill 不自带电子书解析器，也不会自动获取未提供的小说全文。

## 整理出的笔记是什么样

每章先给最容易扫读的内容，再补必要解释。以下是结构示意，括号内是说明，不是某本书的真实情节。

```markdown
# 第006章：原章名

> 本章一句话：谁在什么地方，遇到什么事，局势怎样改变。

接上前文：理解本章必需的前情。

## 先认清这些人
人物、别名、具体辨认提示，以及本章做了什么。

## 场景怎么切换的
默认先给 Mermaid 场景与行动图，再按需补充场景表。
按原文顺序列出时间、地点、视角、在场人物、事件和意义。
特别说明：视角切换不等于人物移动，倒叙不等于事件刚发生。

## 关键因果
为什么发生 → 人物采取什么行动 → 导致什么结果。

## 人物关系变化
默认先给 Mermaid 人物关系图；关系稳定也画本章重要关系。
谁与谁的关系改变了，触发事件是什么。

## 后文真相与本章解释〔含剧透〕
已经核实的真相、揭晓章节，以及本章人物是否知道。

## 本章结束时，记住这些就够了
主要人物现在在哪、下一步目标、障碍和未解问题。

## 背景探究
从原文提出问题，给简答，解释它与剧情的关系。

## 原文定位
完整提取文本入口，以及少量“段号链接＋检索词＋短摘录”。
段号属于对应版本的提取顺序，不冒充纸书页码。
```

**每章默认保留两张 Mermaid 图：场景与行动图、人物关系图。**分别帮助你看清“在哪、怎样切换”和“谁与谁是什么关系”。使用纵向布局、短标签及人物蓝／地点绿等配色；简单章节减少节点和文字，不删掉图。只有原文确实没有对应关系或叙事场景，或你明确要求不画图，才说明原因并省略。因果图可选，不替代这两张默认图，也不把全书塞进一张巨大关系网。

可选的三个短问题帮助回忆，答案放在后面；无需把阅读变成考试。

### 轻量原文定位

采用用户认可的《红楼梦》档案做法：章末通常保留 3–5 处关键定位，例如“段36 · 检索词‘摔’：一小段原文”。点击段号可跳到另存原文页的对应段落，完整正文不塞进笔记，也不会在每个人物页重复复制。

定位优先选择真正发生事件、揭晓身份或解释动机的段落，不能只取某个人名第一次出现的位置。摘录保持短小，校注与正文分清；只有梗概或原文不可读时，明确说明缺口，不生成假的原文链接。

原文页按本版实际段落顺序设置稳定标题（如 `段36`），注明版本、源文件与编号规则。重复整理复用原文页，不默认同时维护 TXT、Markdown、HTML 多套副本；版本或分段变化时须维护映射及链接。原文提取完成、关键段落核对和全书逐段精读是不同状态。

## 阅读 Wiki 的结构

建档时优先沿用你已有目录，新建档案通常采用：

```text
书名-作者或版本标识/
├─ 阅读首页.md          # 进度、材料范围、当前局势与导航
├─ 人物索引.md          # 人物总表＋有来源的小传，集中存放
├─ 故事时间线.md        # 按事件实际时间整理，注明叙述所在章节
├─ 线索追踪.md          # 初现、进展、解释与揭晓章节
├─ 全书速览.md          # 每章一句话、阶段主线与关键因果
├─ 章节/
│  ├─ 第001章-原章名.md
│  └─ 第002章-原章名.md
├─ 人物/                # 可选，只存信息丰富的核心人物档案
├─ 地点与势力/
├─ 文化与背景/
└─ 原文定位/            # 完整提取正文另存，章节只放少量定位入口
```

只整理前几章时，速览会明确覆盖范围；没有有用内容的页面不预先填充空架子。

人物默认集中在 `人物索引.md`：先给辨认总表，再用人物标题归纳“是谁、做过什么、影响了什么、重要变化和来源”。临时人物和资料少的配角不逐人建页，可以直接链接索引内标题。

只有核心人物确有多段关键经历、关系演变、身份或动机解释等至少三类实质信息时，才独立建档。不会生成只剩姓名、身份和返回链接的碎片文件，也不会用空表格、性格套话和“待补充”凑内容。章节主体保留当时的情境，后来揭晓的信息放进独立解释栏目。

知道 Obsidian 仓库根目录时，使用可解析的双链和显示别名；普通 Markdown 交付则使用相对链接。目标页面必须真实存在，并能链接回来源章节。

`阅读首页.md` 会在第一批交付前实际创建，并包含当前覆盖、概要和可用章节导航。交付前运行只读检查脚本，检查返回首页、人物、章节等链接及标题目标；找不到目标就修正路径或改为普通文字，不创建空文件冒充修复。

### 检查已有笔记

有 Python 3 时可运行（将路径换成实际位置）：

```text
python <skill目录>/scripts/check_wiki.py <书籍档案目录>
```

Obsidian 书籍目录只是仓库的一部分时，加 `--vault-root <仓库根目录>`；章节子目录不是 `章节` 时加 `--chapters-dir <目录名>`。脚本只读不修改文件，检查缺失首页、Markdown／双链断链、不存在的标题与区块、空目标和章节缺图；发现错误返回退出码 1，短小独立人物页提示人工审查。检查不等于剧情事实验证或 Mermaid 渲染验证。

旧档案修复时先备份，把零碎人物内容和批注合并到索引、改好入站链接，再归档无引用的旧页；为章节补回有原文依据的两张图。不直接删除个人批注或靠空转跳页处理问题。

**小说笔记应保存到你指定的阅读目录，不要保存到安装 skill 的目录，也不会上传到此 GitHub 仓库。**

## 常用提示词

### 1. 按章整理

```text
使用 $xiaoshuo 整理《书名》第 6–10 章，每章一个文件。
沿用现有阅读 Wiki，同步更新人物、时间线与线索。
```

### 2. 隔了很久，帮我接着读

```text
使用 $xiaoshuo。我读到第 12 章，隔了两周没读。
根据已有档案，用一分钟帮我接上剧情：
主要人物是谁、各在哪里、要做什么、还有什么问题没解决。
需要时补充后文真相，但先还原第 12 章的局势。
```

### 3. 人物记混了

```text
使用 $xiaoshuo。某先生和某个外号是不是同一个人？
查原文或已有笔记，讲清身份、相关经历，并给章节来源。
```

### 4. 理解人物动机

```text
使用 $xiaoshuo。为什么甲在第 8 章突然帮助乙？
允许剧透，请区分本章明确事实、人物说法、推断和后文真相。
```

### 5. 探究文化背景

```text
使用 $xiaoshuo。研究本章的称呼、官职和礼俗。
只选真正影响理解的 1–3 个问题，注明时代、地区和可靠来源，
并解释这些背景如何影响人物的选择。保存到文化与背景目录。
```

### 6. 回顾全书

```text
使用 $xiaoshuo。基于已整理的全部材料，生成五分钟回顾：
每章一句话、故事阶段、关键因果，并提供人物和线索查询入口。
若材料不完整，请明确范围。
```

### 7. 调整剧透设置

```text
使用 $xiaoshuo。这次不要剧透，我只读到第 5 章。
本次输出及新保存的笔记都不要使用之后的信息。
```

已有全书档案可能含剧透，此时助手应提供过滤后的内容或入口；不会擅自删除原来的完整资料。

### 8. 增加回忆问题

```text
使用 $xiaoshuo。每章末尾加三个帮助回忆的问题，
重点问关键原因、人物关系变化和章末状态，答案折叠放在后面。
```

## 文化背景的处理方式

背景页回答四件事：原文为何引出问题、知识是什么、它如何帮助理解剧情、依据及解释边界是什么。

助手应查证具体事实，优先采用原始文献、学术机构、博物馆或官方资料等可靠来源，并附直接链接或准确文献定位。不会把历史知识直接当成小说设定，也不会把创作年代与故事时代混为一谈。

没有检索工具、证据不足或存在争议时，应明确标注待查证或分歧。背景内容不以资料堆砌为目标，而是解释人物的行为、身份压力和情节冲突。

## 更新已安装的 skill

### Windows 已上传 SSH 密钥，但 Git 仍提示 publickey 错误

Windows SSH 代理与 Git 自带的 SSH 客户端有时不会共用同一个代理。若 Windows 代理已经加载密钥，可以先指定 Windows 自带 SSH 测试：

```powershell
& "$env:WINDIR\System32\OpenSSH\ssh-add.exe" -l
git -c core.sshCommand=C:/Windows/System32/OpenSSH/ssh.exe ls-remote git@github.com:zhouyanyu/xiaoshuo-skill.git
```

成功后，可仅对当前仓库配置，不影响全局设置（将路径换成你的 checkout）：

```powershell
git -C "你的checkout路径" config core.sshCommand C:/Windows/System32/OpenSSH/ssh.exe
```

如果 Windows 安装在其他盘符，应使用实际的 Windows SSH 路径。此办法适用于已有可用 Windows SSH 代理的情况，不能代替上传公钥或完成账号认证。

macOS / Linux：

本仓库所有者已要求：**以后帮助更新 `xiaoshuo` skill 时，也同步更新此仓库；使用方法或默认行为变化时同步更新 README。**

同步只包含 skill 和文档，不包含小说全文、个人笔记、凭据或用户目录。正常提交、正常推送，不强推，不覆盖他人的改动。认证失败时明确报告未完成同步。
